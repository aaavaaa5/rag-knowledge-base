背景: V7 架构基于单体应用，随着业务增长出现性能瓶颈，2025 Q3 平均响应延迟从 200ms 恶化至 1.8s。

二、知识库技术选型决策 (2026-03-15)
背景: 公司需要构建内部知识库系统，用于客服、研发、产品多个部门的知识管理。
候选方案对比:
  - 方案A: 使用 OpenAI Embeddings API + Pinecone 向量数据库
    优点: 实施快，准确率高
    缺点: 数据出境合规风险，单条查询成本约 ¥0.03
  - 方案B: 使用本地部署 BGE-M3 模型 + Milvus 向量库
    优点: 数据不出域，成本固定
    缺点: 需要 GPU 服务器投入，初期部署约 3 个月
  - 方案C: 使用阿里云 DashScope 嵌入 + Elasticsearch 向量插件（最终选定）
    理由: 兼顾合规与实施效率，利用现有 ES 集群降低成本，混合搜索（BM25 + 向量检索）效果好
状态: 系统已上线 v1.0，注册用户 1,247 人，文档总数 38,000+ 篇，月均检索量 210 万次。

一、北极光 V7 到 V8 迁移决策
决策日期: 2025-11-03
参与人: 全体技术架构师（9人）、CTO 陈思远、产品VP 王嘉琳
背景: V7 架构基于单体 Ruby on Rails 应用，2019年上线，随着2024年起广告业务和数据分析业务激增，系统逐步出现性能瓶颈。2025年Q3数据显示平均响应延迟从200ms恶化至1.8秒，数据库连接池频繁耗尽，每月出现3到4次P2级别宕机事故。用户反馈系统响应慢的工单数环比增长240%。
决策过程: 2025年10月技术架构评审会上，CTO 陈思远提出三种方案：方案一为垂直扩容（升级硬件），预计延缓1年但成本可控；方案二为微服务重构，预计投入12人年、周期8至10个月；方案三为渐进式重构，引入消息队列缓解压力同时启动部分模块重构。经过两轮投票，全体架构师以7票赞成、2票反对通过微服务重构方案（方案二）。反对票的理由是团队之前没有微服务迁移经验，迁移周期过长会影响业务连续性保障。
最终方案: 采用绞杀者模式（Strangler Pattern），每两周从单体中剥离并迁移一个模块，每个模块迁移后并行运行两周观察稳定性。总共8个模块，预计总迁移周期为8个月。
当前状态: 截至2026年7月已完成6个模块迁移，迁移过程中影响业务的时间累计不超过4小时。剩余计费模块和报表模块计划在2026年9月前完成迁移。
经验教训: 数据迁移阶段遇到了 PolarisFS 分布式文件系统的元数据性能瓶颈，尤其在批量导入历史数据时元数据服务响应延迟飙升。SRE 团队花了3周时间定位后，由存储团队开发了 MetaCache 本地缓存层，将元数据查询延迟从平均350ms降低至12ms。该方案已申请发明专利，申请号为 CN2026xxxxxx.5，发明人为陈思远、李俊杰、王思涵。专利已进入实质审查阶段。

二、内部知识库技术选型决策
决策日期: 2026-03-15
参与人: 平台架构师林晓、AI负责人周宇、安全合规官刘敏、CTO 陈思远
背景: 公司各业务线的知识分散在多个系统中（Confluence、飞书文档、本地文件服务器、GitLab Wiki），搜索不便且权限管理混乱。2025年底员工满意度调研中"信息查找效率"评分仅为3.2分（满分5分），为所有指标中最低分。管理层决定构建统一内部知识库系统，服务范围包括客服、研发、产品运营等多个部门，预计用户数2000人、文档量10万篇级别。
方案对比:
方案A: 使用 OpenAI Embeddings API (text-embedding-3-large) + Pinecone 向量数据库。优点是对外 API 成熟度高，集成速度快，准确率表现优秀。缺点是需要将文档内容发送至海外 API 处理，数据出境涉及合规风险，同时按照10万篇文档估算每月 API 成本约6,000元，且随着量增长成本线性上升。
方案B: 使用本地部署 BGE-M3 嵌入模型（基于 4张 NVIDIA A100 80GB GPU） + Milvus 向量数据库（8节点集群）。优点是所有数据不出公司内部网络，满足合规要求，硬件投入为一次性成本约58万元，长期运维成本可控。缺点是需要3个月左右的部署调优周期，GPU 服务器采购审批流程长，且需要招聘有向量数据库运维经验的SRE。
方案C: 使用阿里云 DashScope 文本嵌入服务（text-embedding-v2） + Elasticsearch 8.x 向量检索插件（基于公司现有 ES 集群扩展）。理由是利用公司已有的3节点 ES 集群扩容至6节点，阿里云嵌入服务部署在国内，数据不出境满足合规要求。混合搜索策略（BM25关键词检索 + 稠密向量检索加权）在内部测试中准确率达到92.3%。成本方面 ES 扩容费用约15万元一次性投入，嵌入服务月均成本约2,800元。
最终决策: 一致通过方案C。CTO 陈思远拍板，理由为"在合规、成本和工程效率之间取得了最佳平衡，同时 ES 是团队已有经验的技术栈，技术风险可控"。安全合规官刘敏补充要求嵌入服务需通过公司数据安全审计，阿里云侧需签署数据处理协议（DPA）。
当前状态: 系统于2026年6月上线 v1.0，已完成与飞书文档、Confluence 的数据迁移。截至7月20日注册用户1,247人，文档总数38,000+篇，月均检索量210万次，用户满意度评分从3.2提升至4.1分。

三、2026年Q2季度战略调整
决策日期: 2026-04-01
会议: Q2 战略委员会（CEO 张明远、CTO 陈思远、CFO 李雪梅、COO 赵晴、两位独立委员张伟和宋涛）
背景: 2026年Q1财报显示营收同比增长降至12%，显著低于年初设定的25%增长目标。广告业务收入环比下降8%，智能硬件产品线亏损扩大至每月320万元。同时行业融资环境趋冷，公司原计划的C轮融资推迟至Q3。
决策内容: CEO 张明远提出"聚焦核心、收缩边界"战略并获得全票通过。具体措施为四条：第一，关停"北极光智能硬件"产品线，该产品线23名员工中8人内部转岗至软件部门、12人协商离职（N+1补偿）、3人调至新加坡分公司负责智能硬件售后技术支持。第二，裁撤日本东京分公司（成立于2021年，共17名员工），日本市场的现有客户和渠道整合至新加坡亚太总部，由新加坡团队远程维护。第三，研发投入占营收比例从15%提升至18%，重点投入三个方向：AI辅助编程工具的自主研发（内部立项代号 CodexAssist）、智能运维平台（内部立项代号 AutoOps）、以及数据中台 V8 的持续演进。第四，全员差旅预算统一缩减40%，非必要不出差，跨城市会议优先使用飞书视频会议，暂停所有海外行业展会参与。
实施效果: 2026年Q2营收同比增长回升至18%，利润率同比提升3.2个百分点。关停日本分公司带来的季度成本节省约130万元。但根据员工满意度调查（2026年6月），"公司发展方向信心"评分从4.0降至3.5，"离职意愿"评分从1.8升至2.3，说明组织调整对团队士气产生了可观测的负面影响。COO 赵晴已要求 HR 部门制定团队文化建设方案，预计在Q3实施。

四、2026年度黑客马拉松结果

主题: "AI 重塑工作流"（AI Reshaping Workflows）
参赛规模: 27支团队、共156人参与，覆盖研发部、产品部、数据部、设计部、运营部，是公司史上参与人数最多的一届黑客马拉松。活动在公司深圳总部3楼和17楼两个场地同时进行，为期24小时不间断开发。
获奖项目:
一等奖（Team Nova，6人）: "CodexFlow" 智能代码审查助手，在 GitLab Merge Request 提交时自动进行代码风格检查、潜在Bug检测和安全漏洞扫描，同时基于项目历史代码模式生成审查建议。当前已集成至公司 GitLab CI 流水线，每天处理约120个MR，审查覆盖率达到85%。一等奖奖金30,000元。
二等奖（Team Aurum，5人）: "PolarInsight" 数据洞察自动生成工具，连接数据中台后自动分析数据变化趋势，生成自然语言描述的数据报告，支持飞书文档导出和 PolarTalk 定时推送。二等奖奖金20,000元。
三等奖（Team Sol，4人）: "MeetingMiner" 会议纪要智能摘要工具，集成至飞书会议机器人，在会议结束后自动生成摘要、待办事项和关键决策点，并关联至对应的项目看板。三等奖奖金10,000元。
后续安排: 三个获奖项目已纳入 Q3 产品路线图。CodexFlow 由研发VP 刘宇轩作为 sponsor，目标在2026年10月前完成 MVP 并推广至全公司使用。PolarInsight 和 MeetingMiner 由数据部门和产品部门联合推进，预计在2026年9月发布内部 beta 版本。
